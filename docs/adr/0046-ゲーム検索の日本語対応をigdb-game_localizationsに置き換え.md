# ADR-0046: ゲーム検索の日本語対応をIGDB game_localizationsに置き換え

## ステータス
承認済み

## 背景
ADR-0045では「IGDBは日本語タイトルを検索できない」という前提のもと、
日本語Wikipediaを橋渡し（日本語記事→言語間リンク→英語名→IGDB再検索）に使う構成を継続し、
その遅さを並列化で緩和する判断をした。

しかし実タイトル検証で「トモダチコレクション」シリーズの続編がヒットしない問題が発覚。
調査の過程でユーザーから共有された記事により、IGDBの `game_localizations` テーブル
（region=3が日本）に日本語タイトル・日本語版ジャケットが登録されており、
`where game_localizations.name ~ *"クエリ"*` で日本語名の直接検索が可能と判明した。
前提が崩れたため、設計を見直す。

## 選択肢

### A案: IGDB game_localizations による日本語検索（Wikipedia橋渡し廃止）
- **これは何か:** IGDBが持つ地域別ローカライズ情報（日本語タイトル・日本語版ジャケット）を
  検索条件と表示に直接使う方式。外部の橋渡しが不要になる。
- **長所:**
  - Wikipediaへの往復（最大10タイトル×2回）が消え、IGDB 2回だけになり大幅に高速
  - Wikipediaで到達不能だった作品（単独記事がない「トモダチコレクション 新生活」等）もヒット
  - シリーズ検索（「ゼルダ」→シリーズ30件等）のヒット率が大幅向上
  - 日本語版ジャケットを表示できる
  - 依存する外部サービスが1つ減り、コードも大幅に簡素化
- **短所:**
  - IGDBのローカライズ登録に依存（未登録のマイナー作品は引き続きヒットしない。
    ただし検証ではムーンライトシンドローム・俺の屍を越えてゆけ等もヒットし、
    Wikipedia橋渡しよりカバレッジが広いことを確認済み）

### B案: Wikipedia橋渡しを継続し、game_localizationsを併用
- **これは何か:** 両方の経路を残してマージする方式。
- **長所:** 理論上のヒット率は最大
- **短所:** 遅さと複雑さが残る。検証の限りWikipedia経路だけがヒットする作品を確認できず、
  維持コストに見合わない

### C案: 現状維持（Wikipedia橋渡しのみ）
- **長所:** 追加作業なし
- **短所:** 続編ヒット問題が未解決のまま。遅い

## 決定
A案。ゲーム検索の日本語対応をIGDB `game_localizations` に一本化し、
Wikipedia橋渡し（`WikipediaGameAdapter`、`WikipediaClient#fetch_english_title` /
`#fetch_categories`、IgdbAdapterの並列補完コード）を削除する。

## 理由
- 検索精度・速度・コードの簡素さのすべてでA案が優位。橋渡しの存在理由だった
  「IGDBは日本語を知らない」という前提自体が誤りだったため
- B案は検証でWikipedia経路の独自貢献を確認できず、複雑さだけが残るため不採用
- `WikipediaClient` 自体は映画・ドラマの正式タイトル解決（TmdbAdapter）と
  記録時の説明補完（WorkEnrichmentService）で引き続き使用する

## 影響
- ADR-0045の「データ取得元（Wikipedia橋渡し継続）」「高速化（並列化）」の判断は本ADRで置き換える
  （関連度ティアソートの判断はそのまま有効）
- 本ブランチで実装したWikipedia補完の並列化コードは、マージ前に削除される
- 検索時のIGDBリクエストは最大2回（keyword＋pattern）になり、初回検索がさらに高速化
- 日本語版ジャケットが優先表示されるようになる
