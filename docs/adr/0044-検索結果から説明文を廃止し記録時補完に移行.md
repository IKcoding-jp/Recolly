# ADR-0044: 検索結果から説明文を廃止し記録時補完に移行

## ステータス
承認済み

## 背景

検索の遅さの根本原因は「検索結果上位20件分の日本語説明補完」（1件あたり最大4回のHTTPリクエスト）だった。
ADR-0042（二段階レスポンス）は体感を隠す策、ADR-0043（1回リクエスト化）は英語表示をなくす策だったが、
どちらも「検索のたびに20件分の説明を補完する」構造自体には手を付けていなかった。

補完系のタイムアウト再試行の無効化などで単ジャンル検索は2〜3秒まで改善したが、
全ジャンル検索は依然30秒級であり、UXとして許容できないというフィードバックを受けて、
「そもそも検索結果に説明文が必要か」を問い直すことになった。

仕様: `docs/superpowers/specs/2026-07-16-search-ui-redesign-design.md`

## 選択肢

### A案: 検索カードから説明文を廃止し、補完を記録時に移す
- **これは何か:** 検索結果を「ジャケット画像＋ジャンル＋タイトル＋記録ボタン」のグリッドにし、説明文を出さない。日本語説明の取得は「記録する」を押した時にその1作品分だけ行い、作品詳細ページで使う。
- **長所:**
  - 検索から重い補完が消え、全ジャンル検索でも常に数秒で完結する（根本解決）
  - 二段階レスポンス・スケルトン等の複雑な仕組みが一切不要になり、コードが大幅に減る
  - 補完対象が20件→1件になり、外部APIへの負荷も激減する
  - 作品の識別はジャケット＋タイトルで足りる（Annict・読書メーター等の類似アプリも同構成）
- **短所:**
  - 検索結果であらすじを確認できなくなる
  - 記録操作が補完の分（典型1〜3秒）長くなることがある

### B案: 二段階レスポンス＋説明欄スケルトン表示
- **これは何か:** 検索結果を先に出し、説明欄はシマー（読み込み中表示）にして、補完が終わり次第日本語説明で埋める。
- **長所:** 説明文を残したまま体感速度を確保できる
- **短所:** 裏では毎回20件分の補完が走り続ける（根本解決にならない）。二段階の状態管理で実装が複雑

### C案: 補完対象件数をさらに絞る（20件→8件程度）
- **これは何か:** 1回リクエストのまま補完する件数を減らして全体を速くする。
- **長所:** 実装が最小
- **短所:** それでも全ジャンル検索は体感10秒前後残る。下位結果は説明なしになり中途半端

## 決定

A案（検索カードから説明文を廃止し、補完を記録時に移す）を採用する。

## 理由

- 遅さの原因である「検索時の一括補完」を構造ごと取り除く唯一の案で、対症療法（B・C案）と違い今後同種の問題が再発しない
- 検索カードの説明文は作品識別にほぼ寄与しておらず、ジャケット主体のUIの方が一覧性も高い
- 説明文が本当に必要な作品詳細ページは記録済み作品にしか存在しないため、記録時の1件補完で必要十分
- B案は実装途中まで進めたうえで比較検討し、根本解決にならないと判断して破棄した

## 影響

- 検索APIから `enrich` パラメータ・`enriched` フィールド・rawキャッシュ（5分）が廃止され、単一パスに戻る（`CACHE_VERSION` v8）
- openBDによるカバー画像補完のみ検索時に残る（ジャケット主体UIのため書影欠損を埋める必要がある）
- シリーズ親説明の流用（`description_from_parent`）は廃止。Season 2系作品は詳細ページの説明が英語/空になるケースがある
- `POST /api/v1/records` の内部で1作品分の説明補完が走る（外部仕様は変更なし）
- ADR-0042は廃止のまま。ADR-0043の「検索結果の説明文は日本語のみ」は「検索結果に説明文を表示しない」に置き換わる
