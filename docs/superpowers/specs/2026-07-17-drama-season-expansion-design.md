# ドラマ検索のシーズン展開 設計書

日付: 2026-07-17
ステータス: 承認済み

## 背景・課題

「コード・ブルー」をドラマ検索すると1件しか表示されない。原因はTMDBのデータ構造にある:

- TMDBはTVシリーズを1エントリとして管理し、各シーズンはその内部データ（`/tv/{id}` 詳細のseasons配列）にしか現れない
- 検索API（`/3/search/tv`）はシリーズ単位で返すため、「コード・ブルー」は1件（初回放送日2008年＝1st seasonに見える）しか出ない
- Recollyのドラマ記録はシーズン単位が理想（アニメはAniListがシーズン別エントリのため、感覚を揃える）

つまり検索アルゴリズムのバグではなく、**TMDBのデータ単位（シリーズ）とRecollyの記録単位（シーズン）のズレ**が本質。

### 対象外と決めたこと

- 劇場版（例: 劇場版コード・ブルー）はドラマタブに混ぜない。現状通り映画タブで検索する（メディア種別の境界を保つ）
- 記録モーダルでのシーズン選択UI（B案）は不採用。検索結果側で展開する方が影響範囲が小さく、アニメとの操作感も揃う

## 設計

### 全体の流れ

```
TMDB検索（現状通り: search/movie + search/tv 並列）
  → TV結果のうち関連度ティアが PARTIAL 以上のものを
     関連度ティア降順 → 人気度降順で並べ、上位3件を選ぶ
  → 各シリーズの詳細（/tv/{id}?language=ja）を並列取得
      ※シリーズID単位で30日キャッシュ（2回目以降は追加レイテンシなし）
  → 通常シーズン（season_number >= 1）が2つ以上あるシリーズは、
     シーズンごとのSearchResultに展開して元のシリーズエントリと置き換える
  → 以降のソート・カバー補完・表示は既存パイプラインのまま
```

- 詳細取得はベストエフォート。失敗・タイムアウト時はシリーズ1件表示のまま（現状と同じ挙動に劣化するだけ）。既存の短タイムアウト並列パターン（supplementary系）を流用する
- 1シーズンのみのシリーズは展開しない（冗長なため）
- 特別編（TMDBのseason 0）は展開対象から除外する
- 展開は `TmdbAdapter#search` の内部で行うため、ドラマタブ検索・全体検索の両方に自然に適用される

### 新クラス: `ExternalApis::TmdbSeasonExpander`

`TmdbAdapter` は既に215行あり、1ファイル200行以内の規約に照らして肥大化を避けるため、シーズン展開ロジックは新クラスに切り出す。

責務: TV系SearchResultの配列を受け取り、展開対象の選定 → 詳細取得 → シーズンエントリへの置き換えを行い、配列を返す。

### シーズンエントリ（SearchResult）の中身

| 項目 | 値 |
|------|-----|
| title | シリーズ名 + 半角スペース + シーズン名（例: 「コード・ブルー　ドクターヘリ緊急救命 2nd season」） |
| media_type | `drama` |
| external_api_id | `{シリーズID}-s{シーズン番号}` 形式（例: `21021-s2`）。既存の `external_api_id` + `external_api_source` 一意制約にそのまま乗る |
| external_api_source | `tmdb` |
| description | シーズンのoverview。空ならシリーズのoverviewにフォールバック |
| cover_image_url | シーズンのposter_path。空ならシリーズのposterにフォールバック |
| metadata.release_date | シーズンのair_date |
| metadata.popularity / vote_average / original_language | シリーズの値を引き継ぐ |
| metadata.season_number | シーズン番号（ソートのタイブレークに使用） |

### ソートの調整（WorkSearchService）

同シリーズのシーズン同士は関連度ティア・品質・人気度が同点になり、順序が不定になる。ソートに第4キー「`metadata.season_number` 昇順（なければ0扱い）」を追加し、1st → 2nd → 3rd の順を保証する。

### キャッシュ

- 検索結果キャッシュ: `WorkSearchService::CACHE_VERSION` を v9 → v10 に上げて旧結果を無効化
- シリーズ詳細キャッシュ: `work_search:tmdb_tv_detail:v1:{シリーズID}` をキーに30日キャッシュ（シーズン構成はほぼ不変。既存のenrichmentキャッシュと同じ方針）。取得失敗時はキャッシュしない（次回再試行）

### 記録時の説明補完との整合

シーズンエントリは検索時点でdescription（シーズンまたはシリーズのoverview）を持つため、記録時補完（ADR-0044）に頼らなくても日本語説明が付く。タイトル「X 2nd season」でのTMDB再検索がTitleMatcherに弾かれても実害はない。

## エラーハンドリング

- 詳細取得の失敗・タイムアウト: そのシリーズは展開せず元のエントリのまま返す（検索全体は落とさない）
- seasons配列が欠損・空: 展開せず元のエントリのまま

## テスト

- RSpec + WebMock（TMDBスタブ）でTDD
- `TmdbSeasonExpander` のユニットテスト: 複数シーズン展開 / 1シーズン非展開 / season 0除外 / overview・posterフォールバック / 詳細取得失敗時のフォールバック / 上位3件制限
- `WorkSearchService` のソートテスト: シーズン番号昇順のタイブレーク
- 既存のTmdbAdapter・検索request specの回帰確認

## 影響範囲

- バックエンドのみ。フロントエンド・DBスキーマ・記録フローの変更なし
- 追加APIコールは検索1回あたり最大3件（初回のみ、以降はキャッシュ）。初回レイテンシ増は1秒前後の見込み
